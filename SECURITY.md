# Security Policy

## Reporting a vulnerability

**Please do not open a public issue for a security problem.**

Report it privately through GitHub's
[Security Advisories](https://github.com/uveshm003/cairn/security/advisories/new)
form, or by email to **uveshmenpur.03@gmail.com**.

Please include:

- what the problem is, and what an attacker gets out of it;
- the steps to reproduce it, and the device and OS version you saw it on;
- the Cairn version or commit.

You should get an acknowledgement within **7 days**. If a fix is needed, I will
tell you the intended timeline and credit you in the release notes unless you
would rather stay anonymous.

## What is in scope

Cairn is a local-only app, so its threat model is mostly about data at rest and
what leaves the device:

- **Anything that causes a network request.** Cairn makes none by design; a path
  that produces one is a vulnerability, not a bug. That includes a dependency
  phoning home.
- **Recordings or database contents readable by another app** — wrong file
  permissions, media landing in shared/external storage, entries leaking through
  content providers, or a backup archive written somewhere world-readable.
- **Leaks through the quick-capture surface** — the home-screen widget,
  quick-settings tile, and their intent contract in
  `android/app/src/main/kotlin/com/example/cairn/`. Anything that lets a third
  party start a recording, or read one, without the user is in scope.
- **Leaks through the share sheet or export** that include more than the entries
  the user chose.
- **Location data captured or persisted when the opt-in setting is off.**
- **Content that reaches the app** — an imported backup archive or picked media
  file that can traverse paths, overwrite files outside the app, or crash the
  importer in an exploitable way.

## What is not in scope

- An attacker with physical access to an unlocked device. Cairn has no app lock;
  it relies on the OS lock screen, and this is a known limitation rather than a
  vulnerability.
- Data recoverable with root or a full device backup. Cairn does not encrypt its
  database or media at rest.
- Findings that require a debug build, a rooted/jailbroken device, or a modified
  APK.
- Reports generated by a scanner with no demonstrated impact.

## Supported versions

Cairn is at v1 and pre-release. Fixes land on `main`; there are no backported
security branches yet.
